fix(i18n): translate the status ids that were rendering straight from data

Found by actually opening the panel on a real instance rather than by a
test: the detail panel showed a green **Online** badge in a Chinese UI while
the sidebar beside it correctly read 在线. The caption is `data.status`, a
stored id, so it never appeared as a `t('…')` literal — and the coverage
sweep could not have caught it anyway, because it demands a leading capital
*and* a space, and these are single lower-case words.

`statusLabel()` already existed in types/index.ts for exactly this, copied
from the main app. It simply was not called at four render sites:

- DetailPanel: the status caption
- BaseNode and ProxmoxGroupNode: the status dot's tooltip
- ScanHistoryModal: the run status, which is a different id set
  ('running' | 'done' | 'cancelled' | 'error') and so needed its own keys

The `capitalize` CSS class that dressed these ids up as titles is dropped:
it was only ever compensating for the untranslated value.

No test changed. The suite asserts the raw ids in the default English
locale, and `t('done')` returns `'done'` there — the key *is* the English
translation, which is the whole reason the dictionary is keyed on source
strings. The eight scan-history assertions still pass untouched.

New guard: status ids rendered from stored data must pass through `t()` or
`statusLabel()`. Verified by reverting two of the four fixes and watching it
fail on both.

2062 tests green, tsc clean.
