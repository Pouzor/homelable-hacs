fix(i18n): merge the node-type part that was never wired up

`zh-CN.ts` imported every part file except `node-types`, so the 43 device
type captions and 8 link type captions sat on disk, passed every "does this
key have a translation?" scan — all of which read the part files rather than
the merged export — and never reached the UI. A node type selected in the
modal showed 'Server' in a Chinese interface.

Found by the new dynamic-text test, which renders the three densest runtime
lookup surfaces instead of only reading the dictionary.

Two new guards, because the existing two could not have caught this:

- every key in every part file must appear in the merged dictionary, and
- every part file on disk must be listed in PART_NAMES, so a new one cannot
  be added without a test checking it.

Both are asserted against the export rather than the parts, which is the
whole point: the gap was between the two.
